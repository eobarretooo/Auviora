# Auviora v0.1.0-alpha.1

**Alpha — early development preview.** Auviora provides an independent Android interface for private local AI, backed by a pinned llama.cpp-omni engine. Model files are obtained separately; no model weights are included in the APK. The current chat accepts text only.

## Added

- Material 3 Chat, Models, Settings and left navigation, with an adaptive sidebar layout.
- Real local streamed text generation, visible engine states and cooperative Stop.
- Verified model download/document-picker import, full SHA-256/size checks, explicit load and unload.
- Basic atomic local conversation history, recent items and title search. Saved histories are read-only.
- Dark/light/system themes, optional Android dynamic colors, English and Brazilian Portuguese.
- Real screenshot gallery, offline demo, source attribution and a controlled release workflow.

## Important fixes

- ARM64 native/OpenMP packaging and 16 KB ELF alignment across all packaged libraries.
- Accurate model/file states and draft preservation during model loading.
- Reliable device-test observation of visible streaming and bounded network teardown verification.

## Install and model setup

When this pre-release is published, obtain `Auviora-v0.1.0-alpha.1-arm64-v8a.apk`, `SHA256SUMS.txt` and the accompanying notices from [GitHub Releases](https://github.com/eobarretooo/Auviora/releases). Verify the exact downloaded APK before opening it:

```powershell
Get-FileHash ./Auviora-v0.1.0-alpha.1-arm64-v8a.apk -Algorithm SHA256
Get-Content ./SHA256SUMS.txt
```

The hash must equal the line for that exact filename. Review Android's installation-source prompt before installing. Package ID: `app.auviora.android`; versionName 0.1.0-alpha.1; versionCode 1. Only ARM64 is packaged. Minimum API 24 (Android 7.0), target API 36; actual hardware evidence is currently one Android 16/API 36 device. No universal RAM/device compatibility guarantee is established.

Open Models, download or import the exact MiniCPM-V 4.7 1B conversion pair (Q4_K_M language model and matching F16 projector, approximately 1.78 GB), keep the app open and explicitly load it. Wait for Ready before sending text. Adequate free storage/memory is required. Arbitrary GGUF files are not interchangeable with the pinned profile. Publisher model terms remain separate from the application license.

## Privacy and offline behavior

Model downloads require internet access. After verified provisioning, generation runs on the device; there is no cloud inference fallback. Offline hardware tests confirm responses with no active default network. This is not a packet-level privacy certification. Conversation history and model files are app-private; Android backup/transfer is disabled.

## Upgrade considerations

The permanent release signing certificate differs from the insecure Android debug certificate. Android cannot normally update an installed debug build with this separately signed release. **Do not uninstall automatically:** uninstalling removes app-private conversations and downloaded GGUF files, potentially requiring another 1.78 GB download. There is no history export/restore UI yet. Use a separate device/profile for release testing, or explicitly decide how to preserve data before removing a debug installation.

Keep the same permanent signing identity for future updates and increase versionCode monotonically. Do not replace this version's published assets or reuse its version number.

## Known limitations

- Agents, background app automation, advanced persistent memory, image attachments and native-context restoration are not implemented.
- The backend includes a vision projector; the current Auviora UI and this release's runtime claims are text-only.
- Compact-model responses can mix languages, invent identity and contain factual/instruction errors. The demo returned eight items for a ten-sentence request.
- Saved histories are read-only; drafts can disappear when navigating away from Chat.
- Downloads run in the foreground and do not support resilient background resume.
- Broad device/tablet, font/TalkBack, SAF-provider and long-session/thermal validation remains open.
- Native cancellation is cooperative and may wait for ongoing prefill work.

## Validation and documentation

The release preparation ran the release configuration, five core JVM tests, release lint without errors, native patch fixtures, exact APK metadata/native/weight/notice/ZIP checks and release-verifier rejection tests. Debug source-regression tests exercise hardware navigation/history plus actual offline inference/streaming. A successful build is not evidence that the signed APK was installed on every supported Android version. Current candidate/signing/publication status is in the [Phase 2.2 report](https://github.com/eobarretooo/Auviora/blob/main/docs/PHASES/PHASE_02_2.md).
